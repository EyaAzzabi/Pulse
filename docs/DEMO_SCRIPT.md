# Five-minute demonstration

1. Start the backend and frontend using README instructions. Open the landing page and choose the interactive demo. This creates an isolated synthetic Northstar Studio organization without a shared privileged password.
2. On the command center, point out the synthetic data label, current cash, overdue receivables and calculated liquidity warning. Open the forecast to see the first negative cash date and the assumptions behind customer collections.
3. Open the copilot and ask “What is my biggest financial risk?” Show its evidence. With no provider configured, explain that this is a deterministic offline financial explanation.
4. Open the Digital Twin. Run the baseline, then simulate an €8,000 purchase. The future balance must decrease without modifying the baseline records. Next accelerate collections and extend supplier payment timing. Compare the minimum balance and shortage date, not just the ending balance.
5. Open invoices and prepare a reminder for an overdue customer. Review the exact recipient and draft in the Decision Center, approve it, then execute. Without delivery configuration it must show a queued/offline result rather than Sent.
6. Return to the dashboard and show that scenario experiments did not change actual cash. Show the decision audit and explain the approval boundary.

Use the values displayed by the running backend. Dates are relative to the seed date, so this script deliberately does not promise a fixed calendar date or a guaranteed recovery. A modeled collection acceleration is an assumption, not a customer payment confirmation.
