# Demo Script (3–5 minutes)

Reset the demo data right before presenting so the story is reproducible:

```bash
cd backend
./.venv/Scripts/python scripts/seed_demo.py
```

This prints a one-time login for `owner@northstarstudio.demo`. Use that
password for the walkthrough below — it is generated fresh each time the
script runs, never hardcoded.

| # | Action | What the audience should see (backend-computed, not scripted) |
|---|---|---|
| 1 | Log in as the Northstar Studio owner | Dashboard loads with real KPI cards: current cash, 30-day net flow, risk level |
| 2 | Point at the risk banner / "biggest risk" indicator | Risk level and reasons come from `GET /financial/summary` — e.g. overdue receivables amount, customer concentration |
| 3 | Open the Forecast view, run a forecast | `POST /forecast/run` returns a 90-day projection; a shortfall date appears if the baseline dips below zero — this is a live computation, the exact date will differ run to run as "today" changes |
| 4 | Ask the Copilot: "What is my biggest financial risk?" | Response cites the same risk reasons as the dashboard (grounded, not generated independently) |
| 5 | Ask the Copilot: "How can I avoid a cash shortage?" | Returns ranked rescue strategies (`GET /recommendations`), each with a real simulated liquidity benefit — not generic advice |
| 6 | Open the Simulator, apply "supplier payment delay +15 days" | Baseline vs. simulated forecast lines diverge; lowest cash point and days-below-zero update to the real simulated numbers |
| 7 | Open Invoices, filter to overdue | See the 3 seeded overdue receivables with real due dates and outstanding amounts |
| 8 | Propose a "send invoice reminder" action for one overdue invoice | `POST /actions/propose` returns a draft email (shown verbatim, not sent) with expected result and risk level |
| 9 | Approve the action | `POST /actions/{id}/approve` — status moves to `APPROVED`; a second approval attempt is rejected (409), demonstrating no-replay |
| 10 | Execute the action | Without `N8N_WEBHOOK_URL` configured, status becomes `QUEUED` with an explicit "not dispatched" reason — call this out explicitly as the honest offline-demo behavior, not a bug |
| 11 | Open Notifications | The execution result appears as a real notification generated by that event |
| 12 | (Optional) Open Decisions / audit trail | Shows the full propose → approve → execute history for that action |

## What NOT to claim live

- Do not say "PULSE sent an email" unless `N8N_WEBHOOK_URL` + SMTP are actually
  configured and the execution result says `SENT`.
- Do not claim the copilot is a general-purpose chatbot — it only answers
  questions it can ground in the financial engine's output.
- If `LLM_PROVIDER=none` (the default with no API key), say so: the copilot is
  running in deterministic/offline mode, which is a deliberate fallback, not a
  degraded demo.
